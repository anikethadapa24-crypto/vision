# TASKS.md — Vision Execution Queue

`ROADMAP.md` maps milestones (weeks each). This file is the granular, near-term work queue those milestones get broken into — tasks sized for a single sitting, ordered top-to-bottom, kept current. It only ever holds the current milestone plus roughly the next one and a half — further out than that, granularity is guesswork that'll just need rewriting when we get there. "Greatest project of all time" isn't a slogan here — it's the Excellence Bar in §1, applied to every single task before it gets checked off.

## 1. Excellence Bar — Definition of Done for Every Task

No task is checked off until all of these are true, not just "code written":

- [ ] Builds clean, no warnings suppressed or ignored
- [ ] Unit tests written and passing for any new logic (not just happy path — the failure mode too)
- [ ] Matches the contracts already committed to: service boundaries in `ARCHITECTURE.md` (no client talking to storage directly, no second writer to the graph), tokens/components in `UI.SPEC.md` (no ad hoc colors or one-off styling)
- [ ] Manually exercised end-to-end, not just unit-tested — backend: hit the RPC from a real client; UI: click through the actual state in a running app
- [ ] No TODO left behind without a corresponding task added to §3 or §4 of this file
- [ ] `PRD.md` / `ARCHITECTURE.md` / `ROADMAP.md` / `UI.SPEC.md` updated in the same change if reality diverged from what they said — the docs stay true, not aspirational
- [ ] Commit message says *why*, matching the repo's commit convention already in use

If a task can't clear this bar in one sitting, it's too big — split it before starting, don't lower the bar.

### M3. Filesystem Watcher + Blob Store — done except delete events & throttling
- [x] Platform watcher wired, scoped to permitted folders — `daemon/vision-daemon/src/watcher.rs`, `notify` crate (wraps `ReadDirectoryChangesW` on Windows via the same crate that would back `FSEvents`/`inotify` on macOS/Linux — only the Windows path has actually been run and tested here, same "compiles elsewhere, verified on Windows only" caveat as M1's transport work). Tracked in §4; coordinated deletion is explicitly M10's job, but *detecting* a filesystem delete is cheap and arguably belongs here — revisit.
- [x] Content-addressed Blob Store — `daemon/vision-core/src/blob.rs`, SHA-256-keyed flat files under `blobs/`, write is idempotent (existing hash = no-op). 4 unit tests.
- [ ] Resource throttling stub (pause watcher callbacks under CPU pressure) — **not implemented**, matches the original task's own "basic, refine in M11" framing; there is currently no throttling at all, not even a stub.
- Found and fixed a real correctness bug while building this: the watcher's first debounce implementation was *leading* (process the first OS event for a path, ignore the rest for 500ms) — on Windows a single `cat > file` can fire a Create event before content is flushed, so the leading approach sometimes indexed a file while it was still empty (observed directly: a real manual run produced "indexed photosynthesis.md (0 chunk(s))"). Fixed by switching to a *trailing* debounce (every event resets a per-path deadline; only ingest once a path has been quiet for 500ms) in `watcher.rs`. Re-verified manually after the fix — same file, same steps, correctly reported "(1 chunk(s))".

## 4. Parking Lot

Ideas, cleanups, or tasks that surface mid-work but aren't part of the current milestone. Capture them here instead of derailing what's in progress — triage into §2/§3 at the start of the next session.

**Session note:** the M2–M7 work above was built in one sitting at the explicit cost of breadth over full fidelity: three deliberate scope calls were made up front — (1) SQLite-backed stand-ins for Kùzu/LanceDB plus a hashing-vectorizer stand-in for the local embedding model, instead of the real native dependencies, to guarantee the pipeline actually compiles and runs today; (2) stop at M7 retrieval, no M8 LLM answer synthesis; (3) no `shell/` Tauri UI work — `examples/repl.rs` is the demo surface. Each stand-in is called out inline above and in its own module doc comment (`stores/graph.rs`, `stores/vectors.rs`, `embed.rs`), not silently treated as the real thing.

- `ARCHITECTURE.md` §7 says a second daemon instance should proxy to the running one, not just refuse to start. Implemented only the refuse-to-start half (`single_instance.rs`) — proxying means the second process would have to detect the first is alive, forward every RPC to it, and exit once done, which is real scope on top of the lock check. Revisit once there's an actual client (Tray App) that would benefit from not just erroring out.
- Pushed the M1 commits on 2026-08-07 and the `#[cfg(unix)]` `serve()` stub *did* break macOS/Linux CI, exactly as flagged as a risk: `examples/client.rs` used `#![cfg(windows)]` at the top of the file, which strips the whole file on non-Windows and leaves no `main` fn (E0601) — cargo still expects every example crate to have one regardless of what's cfg'd out inside it. Fixed by cfg-gating the *body* instead (`#[cfg(windows)] fn main() {...}` / `#[cfg(not(windows))] fn main() { eprintln!(...) }`), same pattern already used in `lib.rs::serve()`. Also had to move `lib.rs`'s `use tonic::transport::Server` etc. inside the `#[cfg(windows)]` fn — they were unconditional and unused-import warnings would have failed the Clippy CI step next, once Build passed. Verified this class of bug with `rustup target add x86_64-unknown-linux-gnu` + `cargo check/clippy --target x86_64-unknown-linux-gnu` before pushing again — `check`/`clippy` don't need a cross-linker, only `build`/`test` do, so this is a cheap way to catch unix-only compile breaks from a Windows dev box going forward.
- **Swap SQLite graph stand-in for real Kùzu** (`stores/graph.rs`): needs a Document/Folder node type distinction, `indexed-in` typed edges (currently there's no edge concept at all, just a flat table), and the `GetGraph(scope)` RPC added to the `.proto` and implemented — currently nothing consumes graph structure, only a flat id→path lookup.
- **Swap SQLite + hashing-vectorizer stand-in for real LanceDB + a local embedding model** (`stores/vectors.rs`, `embed.rs`): real LanceDB gets incremental upsert/delete and an actual ANN index instead of a brute-force scan (matters once past prototype scale, per PRD §7.3's 100K+ node target — M11's benchmark will catch this); a real embedding model (`llama.cpp`-hosted per `ARCHITECTURE.md` §9.1) gets true semantic matching instead of today's lexical/word-overlap matching, and needs the Model Cache + first-run download flow M6 originally scoped.
- **Watcher doesn't handle delete events** (`watcher.rs`) — a file removed from a permitted folder still has live graph/vector/blob/audit rows. Coordinated deletion across all four stores is explicitly M10 scope, but *noticing* the delete and queuing it is arguably cheap enough to fold into M3 rather than wait — revisit.
- **`config.sqlite` has no versioned migration path** — `ConfigStore::open` is `CREATE TABLE IF NOT EXISTS` only. Fine while there's exactly one schema version; build real `PRAGMA user_version`-gated migrations when a second version actually exists, not speculatively now.
- **Resource throttling is entirely absent**, not even a stub — `watcher.rs` ingests every debounced event immediately with no CPU/memory pressure awareness. Original M3 task said "basic stub, refine in M11"; even the basic stub didn't happen this session. Real scope for a future session.
- **Watcher debounce bug found & fixed this session** (see M3 above) — worth remembering as a general lesson: a *leading* debounce (act on the first event, suppress the rest) is wrong whenever the first event can fire before content is stable. Use *trailing* debounce (act after quiet, not after first-seen) for anything reading file content off a watch event.
